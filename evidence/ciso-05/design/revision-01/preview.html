Design review notes

Page Purpose

Primary: 異常Repositoryを発見し、desired／actual差、原因、影響、last-goodを理解して安全な次の操作を選ぶ。

Success: unknown、stale、disconnected、rejectedをhealthy／successと誤認せず、同一pageで対象・原因・回復候補を判断できる。

Out of scope

mode変更、container lifecycle、runner／queue内部操作、PostgreSQL直接接続、任意command／path／credential登録。

Attention hierarchy

  1. Global truth + anomalies: mode、connection、failed／disconnected、desired／actual差、error／recovery。
  2. Diagnostic evidence: last poll／delivery、observed／last-good、queue、active job、delivery attempts。
  3. Safe actions: update、disable、retryはcontextとversionを読んだ後。
  4. Supporting: filter、legend、pagination、review annotations。

Truthful state contract

  • Loading: 結果領域をbusyにし、skeletonをhealthy dataに見せない。
  • Empty: fresh authoritative zero resultだけを「登録なし」と表示。
  • Stale: observed、last-good、reasonを示してcurrent healthyにしない。
  • Disconnected: last knownとlast successful readを区別しmutationを止める。
  • Rejected: 理由と修正方法をaction近傍へ出し、入力を保持。
  • Conflict: current version／attemptを再読込し、自動上書きしない。
  • Success: acceptedではなくauthoritative re-query後だけverified success。

Browser security boundary

  • Browserはsame-origin Control API以外へ接続しない。
  • loopback到達だけを認可とせず、operator session＋exact Origin＋anti-CSRFを要求。
  • bearer／provider／DB／runner／container credentialをbrowserへ公開しない。
  • Registration inputはowner/name＋4 switchesのみ。command、host path、image、mount、credential、任意configurationなし。
  • mode変更、job cancel、container start／stop、DB direct accessはUIに置かない。

Design-system decisions

  • Reuse: Alert。
  • Extend: Repository Status Card、Failure Recovery。
  • Create: Connection/Freshness Banner、Desired/Actual Matrix、Delivery Recovery Panel、truthful state／anomaly-first patterns、status tokens。
  • Feature-local: Registration Editor、safe mutation pattern。
