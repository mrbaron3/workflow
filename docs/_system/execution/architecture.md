## モジュール境界と seam

- **ARCH-execution-001 orchestrator / watch** — 責務: Issue Queue を poll し issue を dispatch、セッションを fan-in、状態を store に確定する**決定論コード**（`DOM-execution-001`）。public な形: `watch(store, config): never`（poll ループ）が一発の run（`driveOnce`）を包む。落ちても store から resume（`ARCH-evaluation-008`）。**実装済み**（execution-loop spec）: `driveOnce`（`pollable` を drain→`driveIssueOnce`＝implement→panel→gate）／`watch`（run-once＋save＋poll cadence の薄い常駐）＝`src/pipeline/execution/loop.ts`。一巡後 issue は `contract-drafted` を離れるため再入は冪等、resume は store 状態のみから成る。generate は seam（mock／実 tmux backend）。**best-of-N（`ARCH-execution-004` sample・ADR-0006 E5）**: 実 drive（`driveIssueLive`）は `runBestOfN` で N sample を回す＝既定 `samples:1`＋first-approve-stop、`measure` で全 sample 完走（pass@k/pass^k 計測）。勝者（最初の approver）を gate 投影し、issue の terminal status は勝者基準で1回だけ適用。
- **ARCH-execution-002 scoping guard** — 責務: dispatch 対象を opt-in に絞る（`DOM-execution-006`）。public な形: `pollable(store, config): Issue[]` ＝ `status==contract-drafted && assignedAgent==config.agent`。未指定／他人所有を除外。
- **ARCH-execution-003 session runner（tmux backend）** — 責務: role ＋ scoped-context ＋ worktree で 1 セッションを spawn し Sentinel を待つ（`DOM-execution-002`）。public な形: `runSession(role, ctx, worktree): SessionResult`。evaluation の AgentRunner（`ARCH-evaluation-002`）の tmux 実装で、backend は pluggable（自前 tmux／将来 Hermes・`LANG-execution-013`・ADR-0005）。**対話セッション（attach 可）であり `claude -p` headless を使わない。**
- **ARCH-execution-004 worktree isolation** — 責務: sample ごとに git worktree を用意/破棄する（`LANG-execution-007`）。public な形: `withWorktree(repo, branch, baseRef): path`。1 sample = 1 worktree、修正ループは同一 worktree を再利用。**完了した生成物は単一の build commit に確定する**（`commitBuild`・修正ループは `--amend` で 1 commit を維持＝`HEAD^` が常に fork 点。`buildChangedFiles = git diff HEAD^..HEAD`）。これで (a) ゲートの `git push` が実 commit を運び、(b) 各 read-only レビューが `createDetachedWorktree` でその build を分離チェックアウトできる（`ARCH-execution-006` の並行パネル）。`.agentops/` は worktree の exclude で git から外す。
- **ARCH-execution-005 sentinel protocol** — 責務: 完了印の契約を定める（`DOM-execution-005`）。public な形: worktree 直下の `.agentops/done.json`（agent が完了時に書く・orchestrator が polling で検知）。tmux 終了検知でなく sentinel を正とする（resume 容易）。
- **ARCH-execution-006 evaluator panel（fan-out / aggregate）** — 責務: Perspective ごとに Evaluator セッションを起こし、その Verdict を集約する（`DOM-execution-003`/`004`）。public な形: `runPanel(pr, perspectives): AggregateVerdict`。evaluation の evaluate/grader（`ARCH-evaluation-003`）を観点数だけ起動し、blocker 観点優先で束ねる。[ADR-0006](../../../decisions/ADR-0006-evaluator-panel-sessions-and-github-pr-gate.md) が実装モデルを確定（E1 観点＝独立セッション・サブエージェント不可／E2 functionality は決定論 grader backend・残 6 観点のみ LLM セッション／E3 evaluator は read-only・出力は観点別 findings を zod 検証／E7 修復は観点横断で発生源観点タグ付き）。各観点は perspective タグ付き EvalRun を 1 件残し、resume は `(prId, attempt, perspective)` 粒度で冪等（`ARCH-execution-009`）。不正な観点出力は握り潰さず `needs-human-review` へ昇格（`ARCH-execution-015`）。**実 backend の招集は並行**（E4・`config.panel.maxConcurrent`・`runPerspectiveSessions`＝`src/pipeline/execution/perspective-session.ts`）: 各レビューは build commit の**分離 detached worktree**（`ARCH-execution-004`）で走り、findings を中央 evalRoot へ集約する。分離により **AC-PANEL-008（採点は成果物を変えない）は構造で成立**（レビューは build の worktree に触れられない）。git worktree の作成/破棄は逐次・セッションのみ並行（レース回避の3相）。自分の checkout を編集したレビューは帰属して discard、stuck はセッション+worktree を生かす。
- **ARCH-execution-007 scoped-context assembler** — 責務: role に最小コンテキストを組む（`LANG-execution-006`）。public な形: `contextFor(issue, systemDir): ScopedContext` ＝ issue の `dependsOnSystem`（id 参照）を system view から解決。汚染防止（`DOM-execution-001`）。**実装済み**＝`src/pipeline/execution/scoped-context.ts`（`resolveSystemContext`＝id→定義行の pure resolver・dangling id は missing として顕在化＝握り潰さない・`renderScopedContext`）。generator セッションへ配線（`buildGeneratorPrompt`）: `config.target.systemDir` 設定時のみ「Referenced design」節を注入し、未設定なら no-op（contract のみ）。**id 参照を都度解決＝コピー snapshot でない**（`LANG-execution-006`）。
- **ARCH-execution-008 legacy/store human review gate** — `config.gate.backend=store` のローカル・手動経路だけが、パネル approve 後に `needs-human-review` で停止し、人間判断を `EvalRun.humanVerdict` へ収穫する（`DOM-execution-007`）。GitHub 経路の現在モデルは ADR-0009 / `ARCH-execution-020..023` であり、current-head Revision Gate 通過後に expected-SHA merge するため、人間 merge を通常の進行条件にしない。`openGate` / `pollGate` / `recordHumanDecision` は legacy/store 互換 seam と false-pass 較正用に残す。
- **ARCH-execution-014 liveness モニタ / surfacing** — 責務: Sentinel 待ちと並行に pane を監視し、stuck（`LANG-execution-014`）を検知して顕在化する（`DOM-execution-009`）。public な形: `monitorLiveness(session, sentinelPath, { idleMs, hardCapMs, pollMs }): 'completed' | 'stuck' | 'timeout'`。判定: pane が `idleMs` 不変 ∧ 作業指標なし ∧ sentinel 無し → stuck；経過 > `hardCapMs` → timeout。stuck/timeout 時: store を `needs-human-review` にし pane スナップショットを evidence 保存、セッションは kill せず `tmux attach` を提示。**自動続行はしない。**

## 共有基盤（Shared Kernel への依存）

- **ARCH-execution-009 store＝source of truth** — セッション/worktree/sentinel は揮発、真実は Issue/PR/EvalRun（`ARCH-evaluation-008`）。orchestrator はどの段で死んでも次の poll が store から在庫を再構成して resume する。
- **ARCH-execution-010 契約＝zod（Published Language）** — セッション入出力（scoped-context・grade 結果）は store の出入りで `domain/schema.ts` により検証される（`ARCH-evaluation-009`）。

## 横断ポリシー

- **決定論の境界**: seam の**外側**（poll/dispatch/grade/store）は決定論コード、**内側**（HOW の遂行）だけが非決定な実エージェント（ADR-0005・`ARCH-evaluation-010` と整合）。mock も tmux も将来の Hermes も「同じ AgentRunner seam の実装違い」に落ちる。
- **headless 非目標**: セッションは対話（attach 可）で人間が介入できる。fire-and-forget の `claude -p` は使わない。GitHub 自動配送では機械ゲートが通常判定を担い、自動処理不能時だけ人間判断へ昇格する。
- **最小コンテキスト**: 各セッションには role 最適な最小情報だけを渡す（木からの id 解決）。ロードマップ全体やコード全体は渡さない。

## アーキテクチャ不変条件

- **ARCH-execution-011** — Orchestrator は決定論コードであり、制御フロー（poll/dispatch/grade/store）を LLM 判断へ委ねない（`DOM-execution-008`）。
- **ARCH-execution-012** — セッションは queue の opt-in 指定（ai-managed）issue のみに生成される（scoping guard・`DOM-execution-006`）。
- **ARCH-execution-013** — sample は Sentinel の出現でのみ grade へ進む（`DOM-execution-005`）。tmux プロセス生存は grade 契機にしない。
- **ARCH-execution-015** — セッションは静かに終了しない: 正常完了は Sentinel、異常停止は liveness surfacing のいずれかで**必ず store に昇格**する（`DOM-execution-009`）。無言 timeout・無言 kill を禁ずる。
- **ARCH-execution-016 gate-before-panel** — パネルは hard gates 通過後にのみ招集される（ADR-0006 E4・`ARCH-evaluation-011` hard-gate-before-score の観点版）。blocking な hard gate が落ちる試行は観点採点に進まず（perspective タグ付き EvalRun を作らず）、gate findings のみを修復へ回す。決定論 grader（`ARCH-evaluation-003`）が gate を先に評価し、LLM 観点セッションにトークンを使わせない。
- **ARCH-execution-017 reviewer workspace / evidence sidecar** — 責務: 評価対象を reviewer の実行副作用から分離しつつ、test 実行で生じた環境副作用を source edit と誤認しない（`DOM-execution-010`）。public な形: `runPerspectiveSessions(buildRef, perspectives): PerspectiveSessionsResult` は (1) Perspective ごとの detached Reviewer Workspace（`ARCH-execution-004`）と checkout 外の Review Evidence Sidecar を作る、(2) reviewer を Reviewer Workspace cwd で起動し findings の絶対 sidecar path だけを出力先として渡す、(3) collection 時に dirty files を `environmentArtifacts | sourceChanges` へ決定論分類する。source/config 変更が1件でもあれば当該 findings を discard して `touchedCode` に帰属する。既知 lockfile のみなら `environmentChanges` に帰属して findings を収集し、completed workspace を破棄する。missing/malformed evidence と late findings の既存昇格意味論（`ARCH-execution-014`/`015`）は変えない。
- **ARCH-execution-018 verification command registry seam** — `config.target.graders.commands[verificationMethod]`を正規registryとし、resolverだけがlegacy `typecheck`/`unit_tests` aliasを解釈する。`groundArtifact`は宣言methodごとにintrinsic checkまたはcommandを解決し、非unit methodはAC単位で環境を注入してshell無しで起動する。未解決はCriterion Verification Evidenceを失敗として生成する。根拠: `DOM-execution-011/012`。
- **ARCH-execution-019 regression parity seam** — Curatorは観測時のmethod commandをEvalTaskへcaptureし、Regression executorはunit_testを共有structured report、その他methodをAC単位commandとして再実行する。current configへのfallbackは同一target・同一methodだけに限定し、別methodを代用しない。根拠: `DOM-execution-011/012`。
- **ARCH-execution-020 PR Revision Gate** — 初回build commit直後にPRを作り、GitHubからcurrent head SHAを取得して`LANG-execution-021`を評価する。EvalRun/Invocation/check/threadはrevision SHAが一致するものだけを集約し、blocking findingがあれば`changes-requested`へ進める（ADR-0009）。
- **ARCH-execution-021 PR-native repair loop** — current revisionのfindingsを既存Repair Briefへ正規化し、同一PR branchへ修正commitをpushする。push後はhead SHAを再取得し、全Perspectiveをfresh sessionで再レビューする。1 turnのfan-out/repairは有限、未完workはstoreからresumeする。
- **ARCH-execution-022 atomic auto-merge and continuation** — merge直前にhead SHA・required checks・blocking threads・mergeabilityを再取得し、Revision Gateが同じSHAでapproveのときだけexpected SHA付きmergeを行う。成功後に`released`と依存解除をstoreへ記録し、同じwatch loopの次issueへ進む。分割Source Issueは全子Issue released時だけ閉じる。
- **ARCH-execution-023 repository PR discovery** — repository registrationを唯一の管理境界とし、各`github-turn`が対象baseのsame-repository Open PRをGitHub current snapshotから列挙する。外部PR番号でStoreへ冪等upsertし、未評価headをcredential非継承・no-toolのdetached reviewへ投入する。Draftはreviewするがreadyまでmergeを保留する。repository-discovered head、およびIssue-pipeline PRでもdurableな`agentGeneratedHeadSha`と一致しない外部更新headは通常の権限付きGenerator repair laneへ入れず、request_changesを保持して外部push後の新headをfresh reviewする。
