## 究極目標（射程・horizon）

人間は「**何を・なぜ（WHAT）**」だけを述べ、それが**証拠付きで確実に動くソフトウェア**に
なる。人間の関与は判断点（WHAT 確定・承認・審査）に限る。

— これは射程であり、広すぎて直接は steer できない。下の北極星を steerable な目標として置く。

## 北極星（steer する目標）

**エージェント群が自律的に開発を行え、その開発プロセスを評価し、改善できる。**
次の三能力で構成する：

1. **自律開発** — 人間が HOW を与えずとも、エージェントが実装まで遂行する。
2. **評価可能** — その開発プロセスと成果を証拠（AC / scorecard / evidence）で評価できる。
3. **改善可能** — 評価から、プロセス自体（grader / prompt / skill / routing / 新エージェント）が改善する。

自律が運用を回し、評価が良し悪しを証拠で判定し、改善が次の自律をより賢くする。
三つが揃って初めて究極目標に近づく。

## 操舵する星（観測指標）

三能力がそれぞれ時間とともに向上する。最優先で steer する一点：
**同じ種類の失敗を二度繰り返さない**（失敗は必ず回帰評価ケースとして捕捉する）。

- 自律: 人間が HOW に触れず進んだ割合 ↑ / issue あたりの人間介入回数 ↓。
- 評価: 証拠で裏付いた判定の割合 ↑ / false-pass 率 ↓。
- 改善: pass@k / pass^k の時間推移 ↑ / 捕捉失敗から育つ eval レジストリ / 修正回数 ↓。

## 誰の・何のため

複数のコーディングエージェント（Claude Code / Codex / Gemini）を継続的・長期的に使う
人間のための、**自己改善する AI 開発組織**。

## 明示的な非目標

- 「自律」は **HOW の自律**であって、WHAT・承認・審査の自律ではない（人間の判断点は消さない）。
- 評価なき自律を目指さない（証拠で判定できない自律は範囲外）。
- 静的運用ではない（評価・改善のない反復ではない）。
- 人手チューニングだけの改善ではない（改善は主に運用の証拠から駆動する）。
- 単発の納品・headless 運用・証拠なき速さ/量の最大化を目的としない。

## 下流トレース（自律 × 評価 × 改善）

```text
究極目標（人間は WHAT のみ）
   ▲
北極星 ──┬─ 自律: roadmap → epic(spec) → issue → AC → 実装（エージェントが HOW を遂行）
         ├─ 評価:                                   → 評価 → scorecard / evidence
         └─ 改善: 失敗・証拠 → Curator（回帰昇格） / Analyst（grader・prompt・skill・routing） ↺
```

spec / issue / AC は WHAT を実現する手段であると同時に、**評価・改善の観測装置**。
evidence と eval レジストリは評価・改善の基質（substrate）。

## 反証（外しているサイン）

- 自律: 人間が HOW に介入しないと開発が進まない。
- 評価: 成果を証拠で判定できず trust に頼る / false-pass が放置される。
- 改善: 時間が経っても賢くならない・同じ失敗が再発する・失敗が回帰化されない。
- 状態が tmux や人の頭の中にあり、resume・監査できない（＝証拠が蓄積されない）。
